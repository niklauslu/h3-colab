## 官方帧格点修正 + 长镜头/竖屏 HD 实测（2026-11-23 · 短剧《守夜人法则》EP01 量产驱动）

> 触发：短剧 EP01 分镜改为 8–13s 多镜长场次（条内 `[Shot N]` 切镜 + 原生对白），此前全程只跑过 124 帧。
> **外壳潜伏 bug**：旧 `frames_for`=(n//4)*4+4 按 4 帧格点取整，历史恰只命中 124（在格点上）所以没炸；
> 按它算出的 76/92/108 全是非法帧。用户贴官方口径后修正。

**官方口径**：`Durations are rounded up to the supported frame grid: 5s → 124 frames (≈5.17s), 15s → 362 frames (≈15.08s)`
→ **合法帧数 = 17k+5**（73 / 90 / 107 / 124 … 362 = 3.04 … 15.08s）。新公式：
`k = max(ceil((round(s×24) − 5) / 17), 4); frames = min(k×17+5, 362)`（h3api.py `frames_for`，配 `import math`）。
验证：3.04/3.75/4.46/5.17s → 73/90/107/124 精确命中；8s→192、10s→243、15s→362。同轮 seconds 下限 4→3。

**重生成语义提醒**：同 prompt/seed/参考换分辨率 = 从新尺寸噪声重新去噪的**新 take**（非超分、非 v2v），构图相近但细节不逐帧一致，HD 版需重新过目。

**流程纪律**：后台长命令（`h3ctl up` / 批量脚本）**不要接 `| tail` 管道**——流式日志被缓冲到结束才吐，期间像卡死。
