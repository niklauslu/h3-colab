## 二、选型过程（一次有价值的弯路）

1. **Noct-Q V4 Uncensored**（基础版 2.1 + DiT 级去审核）：画质好、中文好，但 **25 步在 T4 上 712s/张 ≈ ¥0.16，贵过 API** → 弃
2. 用户拍板 Turbo 速度优先 → **官方 Turbo INT8** 定案
3. Uncensored 事实澄清："Turbo + 真去审核"社区不存在；AtomicChat "Turbo-Uncensored" 仅改文本编码器，实测 45 敏感提示词图像零变化 → **官方 Turbo 即其功能等价物**（无功能损失）
4. abenzerps/Qwen-Image-2.1-Turbo-Quantized 与 Comfy-Org 官方重打包**同一 INT8 文件**（平铺布局，留作备用源）；其 FP8/MLX/NVFP4 档分别需 Ada+/Apple Silicon/Blackwell，T4/L4 均不适用

## 三、T4 vs L4 对照（同 INT8 文件，唯一变量=机器）

| 指标 | T4（15GB，1.15 CU/h） | **L4（24GB，1.67 CU/h）✅** |
|---|---|---|
| 首张（含全量装载 17.3GB） | 91s | **32s** |
| 续出（纯推理，1024×1536） | 69s | **16s（4.3×）** |
| 原生 2K（2048²） | — | **42s** |
| 单张成本 | 0.022 CU ≈ ¥0.016 | **0.0074 CU ≈ ¥0.005（3×）** |
| 显存状态 | 塞满 → 权重流送拖慢 | 全量常驻，零 offload |

**判定：L4 时薪贵 45% 但快 4.3×，每张反而便宜 3×。Qwen-Image 系生产一律 L4。**
T4 保留价值：AI Pro 免费额度时段的兜底档。

## 四、能力实测明细

### 4.1 改图（指令编辑）——坑⑳修复后重测 ✅

> ⚠️ 本节及以下 4.2/4.3 的首轮结果全部作废：参考图列表格式被静默丢弃（坑⑳），首轮"成功"实为纯文生图。
> 修复（点号键）后的真实重测结果如下。

源图：橘猫宇航员 `edit/source.png`（1024×1536）、seed 42：

| 轮次 | 配置 | 耗时 | 结果 |
|---|---|---|---|
| 首轮（参考图未生效） | CFG3 | 26s | 输出"碰巧像"——提示词本身描述了橘猫宇航员，伪验证 |
| **重测（点号键生效）** | **CFG3 + "把宇航员的头盔换成红色棒球帽…"** | **34s** | ✅ **头盔真被替换为红帽、猫脸露出、宇航服/地球背景保持** |

**改图配方**：CFG 3；工作流 `qwen21t_edit_api.json`——`TextEncodeQwenImage21` 加 `vae` + **`"images.image_1": ["10", 0]`** 即为编辑模式，槽位支持 16 张（`<image1>` 标签引用）。CFG1/CFG8 附加观察（首轮，未控参考图变量）：CFG1 倾向叠加而非替换；CFG8 无专用 sigmas 会过曝崩坏。

### 4.2 图生图形式一：指哪改哪（颜色标记区域）✅ 重测通过

机制（官方 Mask Editor / Paint Pen 的 API 等价物）：原图涂色标记区域 → 与原图一起经点号键喂入，提示词指代 "the red-painted area"。

| 轮次 | 配置 | 耗时 | 结果 |
|---|---|---|---|
| 首轮（参考图未生效） | CFG3 + 简短指代 | 26s | ❌ 漂移成另一只猫+噪点背景（无参考可依） |
| **重测（点号键生效）** | **CFG1 + 结构化英文指代** | **23s** | ✅ **红帽精准落在标记位置，猫/宇航服保持** |

**配方**：CFG1 + 英文结构化提示（"The area painted in solid red is a selection mask covering X. Replace it with Y. Keep A/B/C completely unchanged."）。
**已知边界**：8 步全图再生成下背景可能轻微漂移；严格锁定背景需 `SetLatentNoiseMask` 传统 inpaint 模式（待测）。

### 4.3 图生图形式二：参考图合成（人物+场景）✅ 重测通过

双参考图点号键注入（`"images.image_1": ["10",0], "images.image_2": ["11",0]`），提示词 `<image1>`（人物）/`<image2>`（场景）：

- 输入：`compose/ref_char.jpg`（人物，已裁水印）+ `compose/ref_scene.jpg`（雨夜东京小巷）
- **重测 34s，铁证**：人物穿上了参考图的**芥末黄雨衣**+紫发（首轮无效版因无参考，人物穿凭空编造的黑外套）
- 场景灯笼/招牌/湿地忠实还原，透明雨伞带雨珠；样片 `compose/compose_result.png`；工作流 `qwen21t_compose_api.json`

**与视频侧 Ref2VA 呼应**：同一套素材，图生图合成 34s vs 视频生成 209s——"图合成定稿构图 → 喂 FL2VA/Ref2VA 出视频"的高效工作流。
**⚠️ 视频侧 Ref2VA 当年也用列表格式传参考图 + 提示词全描述式，"一次通过"存疑，需 A100 复验（坑⑳同源）。**

### 4.4 透明图（RGBA）✅

| 方案 | 结果 |
|---|---|
| ~~EmptyQwenImageLayeredLatentImage~~（分层潜空间） | ❌ 5D 潜空间 + 专用分层 DiT（`qwen_image_layered_bf16`，另一个模型）——**不是 2.1 的原生路径** |
| **标准 T2I + 提示词要求透明背景** | ✅ **16s，RGBA 直出**：alpha 0~255、四角 ≈0、透明占比 73.6%，棋盘格验证边缘干净（`rgba/rgba_checker.png`） |
| ~~改图抠图（首轮）~~ | ❌ 假阳性：alpha 69.6% 但主体被换成皮包（坑⑳ + 未目检的双重教训） |
| **改图抠图（`<image1>` 标签 + 点号键重测）** | ✅ **41s**：同一紫发人物保持、74.1% 透明、棋盘格验证（`rgba/bgremove_checker.png`） |

**机制**（官方文档确认）：2.1 的 VAE 解码即四通道，透明直接生成在 alpha，非后期抠图。
**注意事项**：下游三通道节点会因 4 通道报错 → 接 `SplitImageWithAlpha` 取 RGB；`JoinImageWithAlpha` 掩码约定 1=透明。
**工作流**：`qwen21t_rgba_api.json`（T2I 透明）；`qwen21t_edit_api.json`（改提示词即抠图）。

## 六、过程中修复的坑（详见 setup-log §12）

- **坑⑰** 守护循环 3s 健康检查在模型装载期误杀 ComfyUI（8 轮循环）→ 60s 超时 + 连续 2 次失败 + 90s 宽限
- **坑⑱** `classify()` 的 `qwen` 关键字把 Turbo DiT 误归 text_encoders → 规范子目录优先
- **坑⑲（认知）** RGBA ≠ 分层模型：`EmptyQwenImageLayeredLatentImage` 属于配套的 Qwen-Image-Layered；2.1 原生 RGBA = VAE 四通道直出，提示词即可
- **坑⑳（最关键）** COMFY_AUTOGROW_V3 的 API 传参考图必须用**扁平点号键** `"images.image_1": ["10", 0]`；
  列表/嵌套字典格式会被 `is_link()` 静默丢弃（[issue #15305](https://github.com/Comfy-Org/ComfyUI/issues/15305)，
  修复 PR #15399）——验证通过、执行"成功"、节点实收 0 张参考图。
  **首批 img2img 结果全部作废**（实为纯文生图：提示词里明写主体的碰巧像，依赖"the subject/person"指代的全部漂移）。
  修复后重测：改图/标记/合成/抠图四项全部真实吃参考图（合成输出人物换上了参考图雨衣即为铁证）。
  **⚠️ 视频侧 Ref2VA 工作流用同一列表格式，Ref2VA 结果存疑待 A100 复验**
- **方法论**：alpha 统计只证格式不证内容——RGBA/改图结果必须目检主体是否保持
